# v1.1.4

## 更新内容

- 打票与降智检测共用可编辑的 JSONL 提示词模板，可在系统设置中修改或恢复默认。默认固定提示词使用英文，保留原有消息分段与 XML 结构，并将个人路径、记忆及 Skills 等内容匿名化。
- 模板按目标账号的时区生成新请求的日期与时区，每次请求独立生成检测挑战；动态挑战继续沿用原有中文规则。
- 降智检测直接通过正常网关调用，不再预先判断是否有票或同步补票。账号选择、API Key 权限、无票策略、限流、票据注入和计费统一沿用正常请求流程。
- 全局打票默认关闭，需要时由管理员手动开启；未明确配置无票策略时，默认允许无票请求。
- 恢复票据中心“当前票据”页中的账号与模型参与开关，切换即保存。缺票或全局打票关闭时仍可编辑，关闭账号参与不会清空各模型选择。
- 全局打票关闭、账号关闭参与或当前模型关闭参与时，缺票不再阻止对应请求的调度与转发；重新开启后恢复已保存的无票策略。
- 全局打票关闭时，账号列表隐藏打票列及对应的列选择选项；重新开启后恢复，并保留用户原有的列显隐偏好。
- 修复缺失票据字段时 SQL NULL 扫描错误导致的请求 500（#15），使普通请求、降智检测和 WebSocket 正确执行无票策略。
- 票据失效仅在实际发送了对应代次的保存票据，且上游返回的 turn-state 与 `__oailb` 同时变化时触发。HTTP 与 WebSocket 真实握手使用同一规则，只影响当前账号、当前模型及请求使用的票据代次。
- 失效流水与票据移除在同一事务中完成，同一代次去重，迟到响应不会删除新补到的票据；失效后通知后台按原有参与规则补票。
- 修复 WebSocket 复用旧连接后重连时，将历史握手状态关联到新票据代次、导致新票被误判失效的问题。
- 网关环境上下文仅改写账号时区，保留客户端原始日期、时间及其他内容；兼容自闭合日期、未转义字符和缺少 kind 标记的完整环境块。
- 移除 HTTP 与 WebSocket 对 Accept-Language 的强制英文改写，沿用原有头部透传及账号显式覆写规则。

## 升级说明

- 升级到 1.1.4 时，会一次性关闭全局打票开关，包括此前已经开启的实例。需要打票时，请在系统设置中重新开启；之后重启不会再次重置。
- 已保存的无票策略、账号和模型参与配置继续保留。无票限制仅在全局打票开启，且账号、当前模型均参与时生效。
- “Codex 打票与降智检测模板”同时作用于两个功能。模板配置无效时，对应打票或检测请求会失败，不会发起上游模型请求；该失败不代表模型降智。
- 历史票据失效流水继续保留。新的失效规则不影响其他模型票据及账号登录状态。
- 真实账号取票率与降智检测效果仍需在实际使用环境中验证。
