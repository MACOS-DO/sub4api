# v1.1.11

## 更新内容

- 合并 SUB2API 0.2.16 ~ 0.2.17 版本。

## 新增功能

- 打票设置新增「打票出口 IP」选项，可选择打票请求从哪个 IP 发出：
  - **使用打票代理池（默认）**：与之前一致，在「IP管理」页配置的 Codex 打票代理池中轮换；池内没有可用代理时不打票，不会直连。
  - **使用账号自身的代理**：用账号绑定的代理打票，打票 IP 与该账号业务请求的出口一致；账号未绑定代理时直连（使用服务器 IP）。
- OpenAI 账号「请求时区」新增「跟随 IP 出口」模式：新建账号、修改账号代理（含批量修改、切回原代理）或切换到该模式后，自动检测出口 IP 所在地的时区，并用于该账号请求的环境上下文；未绑定代理的账号按服务器 IP 检测。编辑账号时可查看检测到的出口 IP、所在地和时区，并可「重新检测」。

## 优化改进

- 优化打票相关设置的提示文案：「打票出口 IP」的每个选项都说明了实际出口与无可用代理时的行为；「IP管理」页的 Codex 打票代理池说明中注明仅在选择代理池模式时生效。
- 选择「使用账号自身的代理」时，手动打票不再因代理池为空而不可用。

## 问题修复

- 修复「IP管理」页 Codex 打票代理池的保存状态与页面显示不一致，导致打票实际使用的代理与所选代理不符的问题：
  - 代理池顶部常驻显示「当前打票轮换」的代理；「打票出口 IP」为账号自身代理时提示代理池不生效。
  - 有未保存的修改时提示并高亮「保存代理池」，离开页面前二次确认；保存后以服务器结果为准。
  - 页面加载完成前不可操作，避免加载结果覆盖刚做的勾选；在本页新增、编辑、删除代理后，代理池列表同步刷新。
  - 已删除或停用但仍被勾选的代理会单独列出、可移除，保存时不再带上；已过期的代理标注「不参与打票」。
- 修复数据库迁移 `241_add_typesafe_platform.sql` 被本地改动后与 SUB2API 上游校验和不一致的问题：该文件恢复为上游原样，存在 OpenAI BPS 账号时由新增的 Sub4API 迁移跳过该约束，并自动修正此前版本记录的校验和，升级时不再报 checksum mismatch；同时新增上游迁移校验和清单与测试，防止再次改动上游迁移文件。

## 升级说明

- 新建 OpenAI 账号的「请求时区」默认为「跟随 IP 出口」；已添加的账号不做修改，继续使用原来的固定时区（默认新加坡），如需跟随出口 IP 请在编辑账号时切换。时区检测失败时沿用上次检测结果，从未成功过则使用新加坡。
- 新设置默认使用打票代理池，升级后打票行为不变；如需改为账号自身的代理，请在「系统设置 → 网关 → Codex」中调整「打票出口 IP」后点击「保存设置」。
- 新版首次启动会自动执行 SUB2API 0.2.16 带来的数据库迁移（分组多语言、Gemini 显式缓存相关表）。
